Add a DBC linter for opendbc, run as `python -m opendbc.can.lint [--json] [--ignore RULE] TARGET...`, where a target is a `.dbc` path or a shipped DBC name (including `*_generated` ones). Exit 1 if anything is reported, else 0; an unknown target or rule name prints an error to stderr and exits 2. `--ignore RULE` (repeatable) turns a rule off.

With `--json`, print a JSON array of findings, sorted by file then line, each with exactly the keys `rule`, `file`, `line`, `message`, `signal` and `text`. `file` and `line` locate the start of the finding's statement. For a path target `file` is the path as given. For a named DBC it is the path, relative to `opendbc/dbc`, of the file holding that line: a generated DBC's template or fragment, or, for text a generator script produces (even an imported fragment), that script, `line` counting within its output. `message` and `signal` are names or null (`signal` null for whole-message findings); `text` is free-form.

Files can include others with `CM_ "IMPORT <path>";`, as the generator does, but recursively. `<path>` is relative to the importing file, and findings in an imported file name it as the importing file's directory joined with `<path>` exactly as written. A file's imports come before its own content, in the order written. Each file is included once per target, however spelled; a target plus its includes is one DBC. `opendbc.can.dbc.DBC(path)` follows imports the same way, skipping those the linter reports.

Repeats are reported on the later definition. `duplicate-message` is a message reusing an earlier ID or name; extended IDs (bit 31 set) compare by their low 29 bits and never clash with standard IDs. `duplicate-signal` is a signal name repeated within a message, `out-of-bounds` a signal with a bit beyond its message's payload, and `overlap` two signals sharing a bit that can both be present in one frame, once per pair, on the later signal. `mixed-endianness` is reported on the `BO_` line of a message mixing Intel (`@1`) and Motorola (`@0`) signals, counting only signals each spanning more than one byte (single-byte signals never count). `duplicate-values` is a second `VAL_` for a signal or one raw value described twice, and `orphan` a `VAL_`, `CM_ BO_`, `CM_ SG_` or `SIG_VALTYPE_` for a message or signal defined nowhere in the DBC (later or in another file counts).

`range` is a `[min|max]` with min above max, or outside what the signal's size, sign, factor and offset can represent, compared exactly; `[0|0]` (unspecified) and floating-point signals are skipped. `impossible-value`, on the `VAL_` line, is a raw value a non-floating-point signal can't hold. `SIG_VALTYPE_ <id> <signal> : <type>;` with type 1 (float) or 2 (double) makes a signal floating-point (type 0 is an ordinary integer), and `value-type`, on the `SIG_VALTYPE_` line (not the `SG_` line), is a float that isn't 32 bits, a double that isn't 64 bits, a floating-point multiplexer switch, or a repeated declaration. When the target has a `BU_` list, even an empty one, `node` is a sender (on the `BO_` line) or any of a signal's comma-separated receivers missing from it, `Vector__XXX` excepted. `import` is an import of a missing file or of one still being imported (a cycle).

In multiplexing, `M` marks a switch, `mN` a signal present when its switch holds N, and `mNM` a signal that is both. Without `SG_MUL_VAL_`, a multiplexed signal's switch is the message's only signal marked just `M` (an `mNM` signal doesn't count). `SG_MUL_VAL_ <id> <signal> <switch> <lo>-<hi>, ...;` instead names the switch and the values selecting a signal (any listed range selects it), with or without an `mN` indicator. Switches can nest, so a signal is present only when every switch up its chain is present and holds a selecting value it can represent. `multiplexer` is reported on the signal's line for a malformed indicator, an `mN` signal whose switch can't be determined, a chain that loops, or a signal that can never be present, and on the `SG_MUL_VAL_` line for a missing message, signal or switch, or a named switch that isn't one.

Message ID 3221225472 (unassigned signals) is skipped for `out-of-bounds`, `overlap`, `mixed-endianness` and `node`. Comments and `BU_` lists may span lines; comments may hold escaped quotes and semicolons.
